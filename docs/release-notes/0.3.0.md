anti-reverse-shield 0.3.0 ships the native library as ready-to-link SDK archives
for every desktop platform and adds scripts that keep a vendored copy current.
The detection code is unchanged from 0.2.0.

### New
- **Native SDK archives** for Linux (x86-64, ARM64), macOS (Apple silicon, Intel)
  and Windows (x64, MSVC): headers, static library, a CMake package
  (`find_package(ars_shield)` → `ars::shield`) and the demo. Every archive is
  built and checked on its own platform (demo run + a `find_package` consumer).
- **`cmake --install`** support in `native/CMakeLists.txt` (`include/`, `lib/`,
  `lib/cmake/ars_shield/`, `bin/ars_demo`), project version 0.3.0.
- **Update scripts**: `scripts/update-sdk.sh` and `scripts/update-sdk.ps1` download
  the newest SDK for the current platform, verify it against `SHA256SUMS.txt` and
  replace `third_party/anti-reverse-shield`; `--check` / `-Check` exits 10 when a
  newer release exists. [docs/UPDATING.md](https://github.com/jongsu-king/anti-reverse-shield/blob/main/docs/UPDATING.md)
  includes a weekly GitHub Actions workflow that opens a pull request.

A library never updates itself inside your shipped program - a protection layer
that downloads code at run time would be a new attack surface. Updates happen in
your source tree, through the scripts above, and reach users with your next build.
